# 원본 구조와 OpenRCA 구현의 대응

| 원본 설계 | 보존한 역할 | OpenRCA에 맞춘 변경 |
|---|---|---|
| 수집 PostgreSQL/Jennifer 입력 | 실제 관측만 분석 | 고정 버전 Parquet 직접 읽기 |
| 분석창·T1~T4 | 시간 순서와 관측 시점 보존 | 제공된 정상·이상 구간을 전체 분석창으로 사용 |
| Ontology | 실제 관측의 객체와 관계 결합 | Client→Server span parent, service→node resource |
| hypothesis.yaml | 근거 조건을 코드와 분리 | 재시작·CPU·메모리·간선 지연·I/O·노드 장애 |
| Thread 생성 | 원인 관측과 후행 영향 연결 | 실제 호출 경로·배치 관계·시간 허용 오차로 후보 구성 |
| Thread 정규화 | 같은 원인과 반복 관측 중복 제거 | 원인 범위·객체·기전별 하나로 병합 |
| 후보 점수 | 관측·연결·독립 근거의 지지 합 | 고정 가중치, 시간 순서와 실제 구조가 맞는 연결만 반영 |
| 최고점 1건 handoff | 최종 후보와 나머지 후보 보존 | `selected_thread` 및 `threads` 모두 저장 |
| INCIDENT | 선택된 근거를 보고하는 후단 | 정답률에 영향을 주는 LLM 재판정은 추가하지 않음 |

T1~T4는 실제 시간창의 네 구간입니다. 없던 초기 원인이나 후행 영향을 채워 넣지 않습니다. 분석창이 10분이면 각 구간은 2분 30초이며, 사례별 창 길이가 다르면 원래 시각을 그대로 유지합니다.

Thread 점수는 `direct_mechanism + baseline_contrast + temporal_ontology_connection + independent_signal`입니다. 가중치 총합은 100이며, 원인 확정 확률 또는 벤치마크 정답률이 아닙니다. 단순한 시간 동시성이나 호출 간선 존재만으로 물리적 장애 원인을 만들지 않습니다.

재시작 지표의 `service_name`이 비어 있으면, 같은 namespace의 정확한 pod/container 식별자에 이미 연결된 서비스 관측을 결합합니다. 여러 서비스가 같은 별칭에 매핑되면 제외합니다. Pod 이름을 잘라 정답 서비스명을 추측하지 않습니다.

이 저장소는 원본의 설계를 이식한 새 구현입니다. 원본의 SQL 중심 조건이나 운영 임계치를 그대로 실행한 결과로 해석할 수 없습니다.
